# Accessible Service Search Page

## Purpose

This page represents the first feature slice of the project: an accessible public-service search experience.

## User Flow

1. User opens the search page.
2. User enters a service name.
3. User submits the search.
4. Results are displayed.
5. User can navigate all controls using the keyboard.

## Accessibility Requirements

- Search input must have a visible label.
- Search button must have an accessible name.
- Keyboard users must be able to reach all controls.
- Focus indicators must remain visible.
- Results must use semantic HTML.
- Error messages must be accessible.
- No unnecessary ARIA attributes should be used.
